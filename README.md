# 會議室預約看板

一個在本機瀏覽器開啟的單頁看板，一眼看出 3 間會議室在某一天的預約狀況，並可快速新增、修改、取消預約，同時避免時段衝突。

- 純前端：無後端、無建置工具、無外部框架或函式庫（包含 CDN）
- 資料存在瀏覽器的 `localStorage`，重新整理或重開瀏覽器後仍會保留
- 單人使用，不需登入或權限

## 功能清單

| 功能 | 說明 |
|------|------|
| 單日時間軸看板 | 3 間會議室（會議室 A／B／C）並排成 3 欄，縱軸 08:00–19:00，每格 1 小時，共 11 格；多小時預約會佔用連續格子 |
| 日期切換 | 「前一天／今天／後一天」按鈕，以及日期選擇器 |
| 新增預約 | 點空白格，輸入會議主題並設定開始／結束時間（僅限整點，至少 1 小時） |
| 修改預約 | 點已預約的格子，可修改主題、會議室、日期、開始與結束時間 |
| 衝突檢查 | 同一會議室、同一天的時段重疊時，拒絕存檔並顯示提示；不同會議室可同時段預約；修改時不會與自己比對 |
| 資料保存 | 所有預約存於 `localStorage` |
| 取消預約 | 每筆預約有「取消」按鈕，先跳出 `confirm()` 確認才刪除，取消後不可復原 |
| 匯出 CSV | 將全部預約（依日期、會議室、開始時間排序）下載為 `bookings-YYYY-MM-DD.csv`，含 UTF-8 BOM 以便 Excel 正確顯示中文 |

> 「匯出 CSV」已實作，但尚未列入 `spec.md` 的功能清單。

不在範圍內的項目（多人使用、後端同步、管理會議室、週／月檢視、重複預約等）請見 [spec.md](spec.md) 的「非目標」。

## 如何開啟使用

不需要安裝任何東西、也不需要啟動伺服器：

1. 取得專案後，直接用 **Chrome 或 Edge**（最新版）雙擊 `index.html` 開啟。
2. 預設顯示今天。點空白格新增預約，點已有預約的格子修改，按「取消」刪除。

注意事項：

- 時間以瀏覽器所在電腦的本機時區計算。
- 資料綁定在「同一個瀏覽器、同一個開啟方式」的 `localStorage`；換瀏覽器或清除網站資料，預約就看不到了。
- 儲存的 key 為 `meeting-room-board:v1`，內容是預約的 JSON 陣列。

### 資料格式

```js
{
  id,                 // 唯一識別碼
  roomId,             // 會議室代碼（A／B／C）
  date: "YYYY-MM-DD", // 日期
  startHour,          // 開始時間，整點 8–18
  endHour,            // 結束時間，整點 9–19，且 endHour > startHour
  title               // 會議主題（必填）
}
```

## 如何執行測試

本專案沒有測試框架，測試是一個獨立的網頁：

1. 用瀏覽器雙擊開啟 `test.html`。
2. 頁面會載入 `app.js`，自動執行 `findConflict` 的 9 個案例，並以表格顯示「預期值／實際值／結果」，頁首顯示「通過 N 項／共 N 項」（全過為綠底、有失敗為紅底）。

涵蓋的情境：完全相同時段、完全錯開、前段／後段重疊、互相包含、緊鄰（12–14 vs 10–12 與 8–10 vs 10–12 皆應允許）、不同會議室同時段。

其餘功能（UI 操作、`localStorage`、取消、匯出等）目前以手動方式，依 [spec.md](spec.md) §6 的驗收標準逐項確認。

### 設計重點

- `findConflict(b, list)` 位於 `app.js`，同時被 `index.html` 與 `test.html` 使用：在 `list` 中找出同會議室、同日期、時段重疊的既有預約並回傳；沒有衝突回傳 `null`；比對時略過相同 `id` 的預約（修改自己不算衝突）。重疊判斷為 `b.startHour < o.endHour && o.startHour < b.endHour`，因此緊鄰的時段不算衝突。
- 專案固定只有 `index.html`、`app.js`、`test.html` 三個程式檔，**不要再拆分其他檔案，也不要引入外部框架或函式庫**。
- 所有介面文字與程式註解使用繁體中文。
